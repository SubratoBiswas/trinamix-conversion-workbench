Run both cleansing-tab checks on open, and say when they are working

The Cleansing tab showed a panel with a heading, a paragraph of explanation, and
nothing under it. That reads as broken. It was not -- both checks on that tab
are lazy, because each builds the sheet frames and that is not free -- but a
silent lazy panel and a failed one look identical, and the analyst has no way to
tell them apart.

  Column rules      already auto-ran on tab open, but rendered NOTHING while it
                    was working. The button showed its loading glyph, which just
                    reads as greyed out. So the one panel that was actually
                    doing something looked the most broken.

  Cleansing findings did not auto-run at all. It said "the check hasn't been
                    run", which was honest, but left the tab's count on 0 and
                    the panel empty for anyone who never pressed the button.

Both now run as soon as the tab is opened, from ONE place -- a single effect
keyed on the tab, rather than the previous trigger buried in the Tabs onChange
handler. Once each: reopening the tab does not re-run them, and a failure is not
retried in a loop. Both buttons stay, for a deliberate re-check.

And both now say what they are doing. "Checking every column against the
template's own header comments..." and "Profiling the source file..." while they
run; "Not checked yet" if they have not been asked. An empty panel now always
means something specific.

  The new useState/useEffect/useRef sit in the top hook block with every other
  hook, above `if (!project) return <PageLoader />`. tests/test_hook_order.py
  enforces that -- it is the rule whose breach blanked this page in the first
  place, and the check caught it here before the code shipped.
