Fix the hook order that blanked Output Preview

OutputPreviewPage declared

  const [fixBusy, setFixBusy] = useState<string | null>(null);
  const [fixNote, setFixNote] = useState<string | null>(null);

roughly 470 lines BELOW

  if (!project) return <PageLoader />;

So the first render -- project still loading -- ran two fewer hooks than the
second. React counts hooks by call order and throws the moment the count
changes: "Rendered more hooks than during the previous render", shipped as
minified error #310. It took the whole page down on every single load, and
before the error boundary landed the symptom was a blank white screen with
nothing on it to act on.

Both hooks now sit with the rest of the component's state, above the guard.
They had been placed next to the handler that reads them, which is why nobody
saw it: the hook looks entirely ordinary there, and the early return is hundreds
of lines away in a 1,600-line component.

THE RULE, CHECKED MECHANICALLY

  tests/test_hook_order.py walks every .tsx file and fails on any hook declared
  below a component-level return. It reads two-space indentation as the
  component's own scope, so a `return` inside a callback is correctly ignored --
  a check that cries wolf is one people learn to skip. Two of its cases feed it
  a known-broken and a known-good component, because a guard nothing can trip is
  not a guard.

  It passes across the whole frontend: Output Preview was the only violation.

DEPLOY SCRIPT

  launch_git.bat no longer runs the test suite -- every patch has the full suite
  run against it before it is cut, and this machine has no Windows venv or
  backend dependencies, so the step could only ever print "cannot run" and ask
  for a keypress. When it misfired it said "tests failed", which was false about

  A patch that will not apply now prints what git actually objected to. "Your

  first half you already deployed, and those need opposite responses -- the
  previous message sent the reader the wrong way.
