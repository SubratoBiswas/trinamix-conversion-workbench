Duplicate scoring: an identical name is a duplicate; a different key is not a defence

Four NextPower supplier rows read

  1416     Nanjing Roytek & 3X Motion Technologies Co., LTD
  3567106  Nanjing Roytek & 3X Motion Technologies Co., LTD
  3567111  Nanjing Roytek & 3X Motion Technologies Co., LTD
  3792588  Nanjing Roytek & 3X Motion Technologies Co., LTD

Byte-identical names. Duplicate suspects reported "Scanned 3813 records -- no
near-duplicate entities above the match threshold."

CAUSE

  _pair_score was a weighted average over every identity field non-blank in BOTH
  rows. The name scored 1.0. The supplier NUMBER, a strong id that differed,
  scored 0.0 and KEPT ITS WEIGHT IN THE DENOMINATOR. So a perfect name match was
  averaged down to roughly 0.5/0.8 = 0.63 against a 0.86 threshold, and the pair
  was discarded.

  Two rows carrying different supplier numbers is the definition of the duplicate
  this function exists to find -- the same company entered twice under two keys.
  The scorer was treating the very thing that makes it a duplicate as proof that
  it was not one.

FIX -- services/entity_resolution.py

  1. An exact normalised-name match short-circuits to confidence 1.0. Legal
     suffixes and punctuation are normalised away first, so "ACME  Inc " and
     "acme, inc." still match, and a blank name never matches another blank name.

  2. A strong id (taxid / number) that DISAGREES now ABSTAINS -- it leaves both
     the numerator and the denominator -- instead of voting against. One that
     AGREES still counts fully, as strong positive evidence. Fuzzy fields are
     unchanged and still contribute in both directions: a name that half matches
     really is weaker evidence, unlike a key that simply differs.

  3. Corroborating evidence is still collected on a short-circuit, so the UI
     keeps listing which fields matched.

  Trade accepted: a few more false pairs on genuinely different companies with
  near-identical names. A suspect is dismissed in one click; a missed duplicate
  ships to Oracle and creates a second supplier record.
