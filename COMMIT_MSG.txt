Error boundary: a page that throws says what broke

Output Preview went white. The console carried `Minified React error #310` and a
stack of one-letter names; the page itself said nothing at all.

React unmounts the entire tree when a render throws and nothing catches it, and
this app had no error boundary anywhere -- the CODEBASE_GUIDE flags exactly this
("there is no error boundary in the frontend, so an unknown type used to unmount
the whole page silently"). So every render bug in the app had the same symptom: a
blank screen, indistinguishable from a failed build, a failed deploy, or a 404
from the static host. All three were considered before the real cause, because
nothing on screen told them apart. A white page is the least informative failure
a UI can have and it is entirely avoidable.

  components/ErrorBoundary.tsx -- catches the throw, names the component nearest
  it from React's componentStack, translates React's numbered production errors
  into a sentence someone can act on, keeps the rest of the app usable, and puts
  the whole report behind one "Copy details" button so a bug report contains the
  stack rather than the word "blank". The full stack still goes to the console.

  Wrapped around <Routes> in App.tsx and keyed on the pathname, so navigating
  away from a broken page clears the error -- without that, one bad route holds
  the app until a manual reload.

  A class, deliberately: componentDidCatch and getDerivedStateFromError exist
  only on classes, and a test says so, because someone will try to convert it.

WHAT IT WILL TELL US

  #310 is "rendered more hooks than during the previous render" -- a hook running
  conditionally, or after an early return that only happens on the first render
  while data is still loading. The component was not identifiable from the
  minified build. With this in place the page names it on sight.

  Not caused by the dated-store or report change: the only hook added anywhere
  was one useState in ProjectOverviewPage, in the top-level hook block with no
  component-level return before it, on a different page.

ALSO OUTSTANDING, NOT CODE

  The static site has no SPA rewrite. render.yaml carries the rule but is
  attached to services named trinamix-backend / trinamix-frontend, while the live
  sites are tx-conversion-workbench and trinamix-conversion-workbench, created by
  hand -- so any deep link or refresh returns 404 with a blank body. Fix in the
  Render dashboard: Redirects/Rewrites -> source /*, destination /index.html,
  action Rewrite.
